Utilisation de tokens CSRF et validation de l'origine des requêtes.

Protections Implémentées

  • ✅ Token CSRF unique par session
  • ✅ Validation du token pour chaque requête sensible
  • ✅ Token avec expiration temporelle
  • ✅ Vérification de l'origine de la requête
  • ✅ SameSite cookie attribute
  • ✅ Double Submit Cookie pattern

Comment fonctionne la protection?

  1. Génération du token: Un token unique est créé pour chaque session
  2. Inclusion dans les formulaires: Le token est ajouté comme champ caché
  3. Validation côté serveur: Chaque requête sensible vérifie le token
  4. Rejet des requêtes invalides: Sans token valide, la requête est refusée
  5. Expiration: Les tokens ont une durée de vie limitée

Autres Techniques de Protection

1. SameSite Cookies

Set-Cookie: sessionId=abc123; SameSite=Strict; Secure; HttpOnly

2. Vérification Origin/Referer

if (request.headers.origin !== 'https://bank.com') {
  return 403; // Forbidden
}

3. Custom Headers

headers: {
  'X-Requested-With': 'XMLHttpRequest',
  'X-CSRF-Token': token
}

4. Double Submit Cookie

Implémentation Serveur (Node.js exemple)

const csrf = require('csurf');

// Middleware CSRF
app.use(csrf({ cookie: true }));

// Route protégée
app.post('/transfer', (req, res) => {
  // Le middleware vérifie automatiquement le token
  // Si invalide, retourne 403
  
  const { to, amount } = req.body;
  // Traiter le transfert...
  res.json({ success: true });
});
