⬆️ #5→#1 A01:2021 - Broken Access Control

Contrôle d'accès cassé - Les utilisateurs peuvent accéder à des ressources non autorisées.

Exemples d'attaques:
  • Modification d'URL: user.php?id=123 → user.php?id=124
  • Élévation de privilèges: user → admin
  • IDOR (Insecure Direct Object Reference)
  • API sans authentification
  • Bypass de vérifications côté client uniquement
🛡️ Protection:
  • Deny by default - tout est interdit sauf autorisé explicitement
  • Vérifications d'accès côté serveur sur chaque requête
  • Ne pas exposer d'IDs séquentiels
  • Utiliser UUIDs au lieu d'entiers
  • Journaliser les échecs d'accès

⬇️ #2→#2 A02:2021 - Cryptographic Failures

Échec cryptographique - Protection inadéquate des données sensibles.

Exemples:
  • Transmission sans HTTPS (données en clair)
  • Mots de passe hashés avec MD5 ou SHA1
  • Stockage de données sensibles en clair
  • Clés de chiffrement en dur dans le code
  • Algorithmes obsolètes (DES, 3DES)
🛡️ Protection:
  • HTTPS partout (TLS 1.2+)
  • Bcrypt/Argon2 pour les mots de passe
  • Chiffrement AES-256 pour les données au repos
  • Gestion sécurisée des clés (HSM, KMS)
  • Pas de données sensibles en cache

⬇️ #1→#3 A03:2021 - Injection

Injection de code - SQL, XSS, commandes OS, etc.

Exemples:
  • SQL: ' OR '1'='1
  • XSS: <script>alert('XSS')</script>
  • Command: ; rm -rf /
  • LDAP: *)(uid=*))(|(uid=*
🛡️ Protection:
  • Requêtes préparées (Prepared Statements)
  • ORM (Object-Relational Mapping)
  • Validation stricte des entrées
  • Échappement des sorties
  • Whitelist de caractères autorisés

🆕 NEW A04:2021 - Insecure Design

Conception non sécurisée - Failles dans la conception même de l'application.

Exemples:
  • Absence de rate limiting (brute force possible)
  • Workflow métier sans validation
  • Pas de défense en profondeur
  • Questions de sécurité prévisibles
  • Architecture monolithique fragile
🛡️ Protection:
  • Threat modeling dès la conception
  • Secure design patterns
  • Revue d'architecture par des experts
  • Tests de sécurité intégrés au dev
  • DevSecOps

⬆️ #6→#5 A05:2021 - Security Misconfiguration

Mauvaise configuration - Paramètres non sécurisés.

Exemples:
  • Comptes par défaut (admin/admin)
  • Directory listing activé
  • Stack traces visibles
  • CORS mal configuré
  • Headers de sécurité manquants
🛡️ Protection:
  • Configuration sécurisée par défaut
  • Désactiver fonctionnalités inutilisées
  • Headers: CSP, HSTS, X-Frame-Options
  • Erreurs génériques en production
  • Audits de configuration réguliers

⬆️ #9→#6 A06:2021 - Vulnerable and Outdated Components

Composants vulnérables - Dépendances avec CVE connus.

Exemples:
  • Apache Struts vulnérable (Equifax breach)
  • Log4Shell (CVE-2021-44228)
  • Bibliothèques npm non maintenues
  • WordPress plugins obsolètes
🛡️ Protection:
  • npm audit ou pip-audit
  • Dependabot / Renovate
  • SBOM (Software Bill of Materials)
  • Patch management
  • Retirer dépendances inutilisées

⬇️ #2→#7 A07:2021 - Identification and Authentication Failures

Échecs d'authentification - Failles dans la gestion des identités.

Exemples:
  • Brute force sans rate limiting
  • Mots de passe faibles acceptés
  • Sessions qui n'expirent pas
  • Pas de MFA disponible
  • Récupération de mot de passe non sécurisée
🛡️ Protection:
  • MFA (Multi-Factor Authentication)
  • Politique de mots de passe forts
  • Rate limiting sur login
  • Sessions avec timeout
  • Pas de credential stuffing

🆕 NEW A08:2021 - Software and Data Integrity Failures

Échecs d'intégrité - Code et données non vérifiés.

Exemples:
  • CDN compromis (JavaScript malveillant)
  • Updates automatiques non signés
  • Pipeline CI/CD non sécurisé
  • Désérialisation non sécurisée
🛡️ Protection:
  • Subresource Integrity (SRI)
  • Signature de code
  • CI/CD pipeline sécurisé
  • Vérification des checksums
  • Éviter désérialisation de données non fiables

⬇️ #10→#9 A09:2021 - Security Logging and Monitoring Failures

Échecs de journalisation - Manque de visibilité.

Problèmes:
  • Connexions échouées non loggées
  • Logs non surveillés
  • Pas d'alertes temps réel
  • Logs facilement effaçables
🛡️ Protection:
  • Logger tous événements critiques
  • SIEM (Security Information and Event Management)
  • Alertes automatiques
  • Logs immuables et centralisés
  • Plan de réponse aux incidents

🆕 NEW A10:2021 - Server-Side Request Forgery (SSRF)

SSRF - Application récupère des URLs non validées.

Exemples d'attaques:
  • Accès métadonnées cloud: http://169.254.169.254/
  • Scan réseau interne
  • Bypass de firewall
  • Lecture de fichiers locaux: file:///etc/passwd
🛡️ Protection:
  • Whitelist stricte d'URLs/domaines
  • Pas de redirection d'URL utilisateur
  • Validation schema (http/https seulement)
  • Firewall entre app et réseau interne
  • Désactiver redirections HTTP
